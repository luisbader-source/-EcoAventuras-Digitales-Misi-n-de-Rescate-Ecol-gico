Publicación y Compartición de Informes en Power BI

🔍

Bienvenido a la Sesión 4 del curso de Power BI impartido por CINTIA Unicórdoba. En esta sesión final nos enfocaremos en la publicación y compartición de informes, seguridad a nivel de fila (RLS) y distribución masiva a través de aplicaciones Power BI. 🚀✨

Aprenderemos a utilizar Power BI Service, configurar workspaces, implementar seguridad RLS, crear aplicaciones para distribución masiva, configurar alertas y suscripciones, y utilizar Data Gateway para actualización automática. El contenido está estructurado en 7 módulos que te convertirán en un experto en la publicación y compartición de informes.

Objetivos de aprendizaje

  • 🌐 Diferenciar entre Power BI Desktop y Power BI Service, comprendiendo sus roles complementarios en el flujo de trabajo.
  • 📤 Publicar informes desde Desktop a Service y gestionar workspaces para organizar el contenido.
  • 🔐 Configurar seguridad a nivel de fila (RLS) para restringir el acceso a datos según el usuario autenticado.
  • 👥 Compartir informes con permisos y roles, y crear aplicaciones Power BI para distribución masiva.
  • 🔔 Configurar alertas de datos y suscripciones a reportes para mantenerse informado automáticamente.

🌐 Dos herramientas complementarias

Power BI Desktop y Power BI Service son dos herramientas que trabajan juntas en el flujo de trabajo de Business Intelligence, cada una con su rol específico.

💡 Concepto clave:

Desktop es para crear y modelar; Service es para publicar, compartir y colaborar.

📊 Comparación: Power BI Desktop vs Service

💻 Power BI Desktop
  • • Aplicación Windows (gratuita)
  • • Modelado y transformación de datos
  • • Crear visualizaciones y reportes
  • • Escribir medidas DAX
  • • Archivo local .pbix
  • • SIN colaboración en tiempo real
☁️ Power BI Service
  • • Plataforma web en la nube (app.powerbi.com)
  • • Publicar, compartir y colaborar
  • • Dashboards interactivos en el navegador
  • • Permisos, roles y seguridad RLS
  • • Aplicaciones, alertas y suscripciones
  • • Acceso móvil (iOS / Android)

📤 Publicar desde Desktop a Service

El proceso de publicación lleva tu reporte desde el archivo local .pbix a la nube de Power BI Service.

📋 Pasos para publicar:

  1. Abre tu reporte en Power BI Desktop
  2. Clic en el botón "Publicar" en la cinta de opciones
  3. Selecciona el workspace de destino
  4. El reporte se publica en app.powerbi.com
  5. El dataset y el reporte viajan juntos al Service

🗂️ Workspaces: Organización del Contenido

Los workspaces son contenedores para organizar reportes, dashboards y datasets en Power BI Service.

📌 Crear un Workspace:
  1. En Power BI Service, navega a "Workspaces"
  2. Clic en "Crear workspace"
  3. Asigna un nombre descriptivo
  4. Agrega miembros con roles apropiados
  5. Organiza contenido por departamento o proyecto

💡 Nota importante: Un workspace bien organizado facilita la colaboración y el mantenimiento de los reportes a largo plazo.

👥 Roles en un Workspace

Los roles determinan qué pueden hacer los usuarios dentro de un workspace de Power BI Service.

👑 Administrador

Control total: editar, publicar, compartir, gestionar miembros y permisos

👤 Miembro

Puede publicar, editar y compartir contenido dentro del workspace

🤝 Colaborador

Puede editar y compartir, pero no puede publicar nuevo contenido

👁️ Visor

Solo puede ver el contenido, no puede editar ni compartir

🔐 Compartir Reportes

📋 Opciones de compartición:
  • Compartir directamente: Enviar enlace a usuarios específicos
  • Publicar en workspace: Disponible para miembros del workspace
  • Crear aplicación: Distribución masiva a grupos grandes
  • Embed: Insertar en SharePoint, Teams o sitios web
⚠️ Consideraciones de seguridad:
  • • Verifica permisos antes de compartir
  • • Nunca publiques en 'Todos' sin aprobación
  • • Usa RLS si hay datos sensibles
  • • Revisa destinatarios del enlace

🔒 Row-Level Security (RLS)

RLS restringe el acceso a filas de datos según el usuario autenticado. Cada persona ve solo la información correspondiente a su dependencia, sede o rol, sin necesidad de crear múltiples reportes.

⚠️ Importante:

RLS se configura en Power BI Desktop y viaja con el .pbix al Service. Los usuarios se asignan a roles en el Service.

⚙️ Configurar RLS en Power BI Desktop

1️⃣ Abrir Gestión de Roles

Modelado → Administrar roles → Nuevo rol

2️⃣ Nombrar el rol

Ej: Rol_Ingeniería · Rol_Bienestar · Rol_RRHH

3️⃣ Definir filtro DAX

[Dependencia] = USERPRINCIPALNAME() o [Dependencia] = "Ingeniería"

4️⃣ Guardar y publicar

Publicar a Service → el rol viaja con el .pbix

5️⃣ Asignar usuarios al rol

Service → Dataset → Seguridad → Agregar email al rol

📊 Ejemplo Unicordoba

Decano de Ingeniería: Ve solo datos de Ingeniería

Bienestar Universitario: Ve solo su dependencia

📱 Aplicaciones Power BI

Las aplicaciones Power BI permiten distribuir reportes a grupos grandes de usuarios de manera controlada y personalizada.

💡 Ventajas de las Apps:

  • • Distribución masiva a grupos de seguridad o listas de distribución
  • • Navegación personalizada para los usuarios finales
  • • Branding y personalización de la interfaz
  • • Control centralizado de accesos y permisos

⚙️ Crear una Aplicación

1️⃣ Seleccionar contenido

Elige los reportes, dashboards y datasets del workspace

2️⃣ Configurar navegación

Personaliza el orden y la estructura de navegación

3️⃣ Definir accesos

Asigna grupos de seguridad o listas de distribución

4️⃣ Publicar la App

Los usuarios reciben notificación y acceso automático

🔔 Alertas de Datos y Suscripciones

Mantente informado automáticamente sin abrir Power BI. Las alertas y suscripciones te notifican cuando ocurren eventos importantes en tus datos.

🚨 Alertas de Datos

Recibe una notificación cuando un KPI supera (o baja de) un umbral definido.

  • • Solo funcionan en visuales tipo Tarjeta, KPI o Medidor
  • • Dashboard en Service → … → Administrar alertas
  • • Define: condición + umbral + frecuencia
  • • Notificación vía email y Centro de notificaciones
📧 Suscripciones a Reportes

Recibe capturas de pantalla de un reporte por email según una programación.

  • • Abre el reporte en Power BI Service
  • • Clic en Suscribirse → Agregar suscripción
  • • Define frecuencia: diaria, semanal, horaria
  • • Agrega destinatarios (email)

💡 Ejemplos prácticos: Alerta si Activos < 350 → email automático al jefe de RRHH. Reporte semanal de matrículas cada lunes 7am a 3 decanos.

🔄 Data Gateway: Conexión On-Premise

Data Gateway conecta el Power BI Service en la nube con tus bases de datos on-premise, permitiendo actualizaciones automáticas de datos.

🏗️ Arquitectura del Gateway

Base de datos On-Premise
→
Power BI Gateway
→
Power BI Service
→
Usuarios

⚙️ Configurar Gateway en 4 pasos

1️⃣ Descargar e instalar

powerbi.microsoft.com → Descargar Gateway → instalar en servidor con acceso a BD local

2️⃣ Registrar en Service

Iniciar sesión con cuenta organizacional → el gateway queda registrado en el tenant

3️⃣ Agregar fuente de datos

Service → Configuración → Gateways → Agregar fuente de datos → ingresar credenciales BD

4️⃣ Programar actualización

Dataset → Programar actualización → definir frecuencia (diaria, cada hora, etc.)
